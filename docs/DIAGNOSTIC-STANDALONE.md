# 诊断版独立包

这个包用于定位“诊断状态可见、拖动输入正常，但角色没有形变”的问题。
第三修订版（2026-10-15）沿用正常版的 EFMI、XXMI 库、触摸算法和 picker 缓存，保留
只读 GPU 数值面板、`log_level=info` 初始化日志、INI 警告和诊断收集器。
保留输入日志设置，但不把“有按键记录”当成“GPU 拾取成功”。不会自动修复缓存时间戳。

## 使用前

1. 退出游戏和其他 XXMI 实例，官方游戏启动器可以保持打开。
2. 将整个诊断包解压到可写目录，例如 `D:\EndfieldJiggle-Diagnostic`。
3. 不要放进 `Program Files`、游戏目录或旧 EFMI 目录。
   使用 `D:\EJD` 这类短目录，避免缓存名超出当前上游渲染库的固定长度缓冲区。
   新版启动器会在加载前检查包内 HLSL 的缓存路径长度。
4. 第一次测试不要复制旧包的 `launch-settings.json`、`d3dx_user.ini`、`Logs` 或 `ShaderCache`。
5. 打开 `EndfieldJiggleLauncher.exe`，选择实际的 `Endfield.exe`，点击“等待官方启动”。
6. 在官方游戏启动器确认 **DirectX 11**，再点击官方的开始游戏；游戏必须在开始等待之后启动。
7. 等待本包显示 EFMI 已加载后进入游戏。不再直接运行游戏 EXE，也不能自动附加 DX11 参数。
   等待最多 5 分钟，可取消；取消不结束游戏、不卸载已加载的 DLL。

本修订不更换注入 DLL，也不绕过安全策略。若官方安全校验拒绝加载，请停止测试并导出日志，
不要关闭反作弊、安全软件或修改其组件。新启动流程尚未经过真实游戏验证。
2026-10-15 进程查询修正版同时修复启动器核验路径时的 `299` / `5`：
不再枚举游戏模块。若有限权限查询仍被拒绝，保留原错误并停止加载。

## 必须完成的测试

按 `Ctrl+Shift+F9` 显示原有状态，再按 `Ctrl+Shift+F6` 显示 GPU 数值面板。
数值面板默认关闭；再次按同一组合键可关闭，不改变触摸参数。
每项持续几秒并记录完整面板截图：

1. 进入原版干员总览，确认角色完整显示。
2. 关闭触摸，移动鼠标但不要按键，确认画面不变。
3. 按 `Ctrl+Shift+F8` 开启触摸，等待 3 秒。
4. 按住 `Shift + 鼠标左键`，分别在皮肤、衣服和头发区域拖动约 2 秒。
5. 松开鼠标但保持 `Shift`，再松开 `Shift`，观察回弹。
6. 换到第二名原版干员重复拖动。
7. 截取静止、按住拖动、松开后的三张数值面板截图。保留正常版触摸参数。
8. 若没有效果，可对比游戏窗口模式/无边框模式，但不要求关闭系统安全软件或更改驱动。
9. 关闭诊断面板并退出游戏。一次测试只运行几分钟，诊断包不是长期游玩包。

不要按 `Shift+F11`，不要启用 FrameAnalysis，不要打开 `debug = 1`。
这些会产生巨大文件，本诊断不需要。本包清空 FrameAnalysis 的快捷键绑定、
关闭 API 调用和超详细 debug 日志及 crash dump。收集器只读取，不删除原日志。

## 导出

退出游戏后双击包根目录的 `Collect-Diagnostics.cmd`。它会生成 `Diagnostics` 文件夹和 ZIP，包含：

- Windows 版本、显卡型号和驱动版本；
- VC++ 运行库是否存在、官方加载库是否实际可加载；
- 硬件及 WARP 离线 D3D11 设备能否创建、达到的 feature level；
- 所有发布文件的大小和 SHA-256 与包内基准是否匹配；
- 原四组及新增诊断着色器的 HLSL/缓存 FILETIME 是否一致；
- `d3dx.ini` 相关设置；
- 启动器日志和 D3D11 日志中的筛选行。
- `launch-summary.json`：启动模式和最近启动阶段，区分等待游戏、检测到游戏、开始加载及加载确认。
- `path-budget.json`：发布 HLSL 路径及预留缓存后缀后的长度，不移动文件，不覆盖外部自定义 include。

收集器支持 Windows 自带 PowerShell 5.1，不要求用户安装 PowerShell 7/.NET SDK。
每份日志最多读取开头 16 MiB 与末尾 4 MiB；编译错误、着色器信息与输入记录
分开保留，避免按键日志挤掉启动错误。超过范围的中间部分不扫描，
没有找到错误不代表整份日志不存在错误。

自动检查包根目录、EFMI 目录和已保存的游戏目录中的日志。文件被占用、
WMI 或本机探测失败会记入报告；不应把检查缺失当成检查通过。
路径和 UID 尽力脱敏，不保证日志绝无个人信息。分享前检查 ZIP，
并另外发送三张 GPU 数值面板截图。收集器不上传，也不修改游戏/Mod 文件。
若连游戏或 EFMI 都未成功加载，直接导出即可，不需要等待游戏内截图。

## 数值行

面板左侧显示行号，按以下含义读取：

| 行 | 四个值从左到右 |
| --- | --- |
| 0 | 原生绘制数、颜色绘制数、会话完成、拖动输入 |
| 1 | 鼠标 X、鼠标 Y、窗口宽、窗口高 |
| 2 | 实时拾取世界坐标 XYZ、命中标记 W |
| 3 | 保留值、计算时拾取有效、运动激活、之前按住 |
| 4 | 形变偏移 XYZ、形变激活标记 W |
| 5 | 输入控制器状态 |
| 6 | 触摸开关、取消标记、picker 已开始、DPI |
| 7 | 表面法线 XYZ、深度 |
| 8 | 捕获记录 |
| 9 | 半径、最大位移、Y 翻转、运行时间 |
| 10 | 诊断日期/修订/执行标记，应显示 `1014 2 1 0` |

第 2 行 W 一直为 0，重点查拾取；命中为 1 而第 4 行不产生偏移，
重点查捕获/计算；第 4 行已经有偏移但角色不动，重点查最终顶点绘制应用。
这是观测值，不是自动根因判定，也不能证明所有角色/部位兼容。
第三修订版只调整启动与日志收集，GPU 面板仍使用第二修订版的 `1014 2 1 0` 标记。
第 10 行缺失或面板完全不显示时，先检查诊断着色器加载错误。

## 状态含义

- `NO COMPATIBLE NATIVE PROGRAM`：没有匹配到当前原生着色器。
- `NATIVE PIPELINE WARMUP`：找到兼容绘制，但会话尚未连续预热完成。
- `NATIVE PIPELINE / TOUCH ON`：触摸开关已启用，不代表拾取成功。
- `NATIVE PIPELINE / DRAG INPUT HELD`：拖动输入已读取，不代表一定拾取到了角色。
- `EFMI MODS DISABLED`：EFMI 总 Mod 开关关闭。
