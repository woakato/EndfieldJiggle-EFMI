# QAQM 状态文件恢复

## 完整程序的通用检查

“换装适配”页的“检查 QAQM 状态”读取 EFMI 当前 include 图、递归目录及排除规则，
检查换装实际引用的 Bridge ID。已加载且声明齐全的状态不会再生成第二份。
只有同一源 INI 的 `.qaqm-persistbak` 能证明缺失变量和数值默认值时，
“补齐缺失状态”才可使用。缺少来源、重复宿主或不明确的依赖会报告并停止。
不逐角色登记，不分发其他作者的换装，不改 UI 绘制或全局持久化文件。

恢复前须退出游戏与 XXMI；生成文件保存在所选换装根目录，
凭据和备份在 `DISABLED_EJQaqmBackups/`。撤销只删除本工具生成且未被改动的文件。
QAQM 管理器之后若改变 include 列表，应重新检查，避免两处加载同一 namespace。

## 旧独立补丁

这是与 v0.2.1 运行时分开的恢复补丁，不包含换装模型或纹理。
仅适用于导出报告指明的同一套换装。不要给其他 Mod 或其他 Bridge ID 使用。

2026-10-08 的提弗洛斯 EJTouch 适配包依赖外部 QAQM 状态宿主，
当前明确的 include 列表未加载换装的 `Bridge_cdfe9cf828d1`。
UI 的 `Bridge_3f2e579b50a9` 已在外部加载，因此不能重复声明。
本补丁从对应 `.qaqm-persistbak` 中恢复变量名和初始值，保留现有
QAQM namespace。不修改换装绘制、按键条件或 UI 命令。

1. 完全退出游戏与 XXMI，备份现有换装目录。
2. 确认该目录缺少同名 `qaqm_state_*.ini`；若已有，不要覆盖，先核对报告。
3. 将补丁中缺失的 `qaqm_state_*.ini` 放入当前启用的 `EJTouch_...` 根目录。
   不要同时放入原换装和适配换装并启用两份。
4. UI 的 `k` 子目录若先前被停用，需要在退出状态下重新启用它才能复测 UI。
   只恢复状态文件不会擅自开启原目录或界面。若 QAQM 管理器重新生成了
   外部 include 列表，请重新检查：同一 Bridge ID 只能保留一个已加载宿主。
5. 使用 v0.2.1 运行时完整重启游戏，先看模型和 UI，再开启触摸。

已有 `d3dx_user.ini` 中同 namespace 的持久化值应由加载器正常读取；
本补丁不覆盖或清空该文件。升级后的首轮测试请保留新日志。
移除补丁时只移走本次新增的状态文件，原始换装和备份不动。

本恢复补丁的加载器解析验证和游戏内 UI/角色验证分别记录。
不能把本补丁当作对全部 QAQM 或 F10 模型消失问题的通用修复。
新完整包不要求下载这个按 Bridge ID 固定的补丁，应优先使用上面的实际依赖检查。
