# v0.2.7 目录修复（修订 2）

单份完整运行时支持旧目录、中文分类目录和多层嵌套。判断是否完整时，现在
同时检查实际着色器文件；不再将“能读取 INI”显示为健康安装。

如果只改名了旧包的 `shaders` 或 `Configurator` 子目录，旧包根目录的
`EndfieldJiggle.ini`、`Passes.ini`、`Outfits.ini` 和 `OutfitPreparation.ini`
仍可能被 EFMI 加载。它们与另一份完整包共享入口，可能导致重复段、错误的
着色器相对路径以及触摸失效。移动新版目录无法消除这些旧入口。

## 自动修复

1. 退出游戏和 XXMI。
2. 从本次修订的拖放包打开 `Configurator/EndfieldJiggleConfigurator.exe`。
3. 在“安装与恢复”点击“修复目录”，选择要保留的触摸目录。可选择旧目录、
   新版解压目录或分类目录内的实际运行时。
4. 核对预览中的目标目录、旧 INI 清单和待补齐文件后执行修复。
5. 重新通过原来的启动器启动游戏，按 Alt 加鼠标左键拖动。

修复保留所选目录的可读取按键与强度，补齐本版自有文件，并将其他触摸副本
的已识别活动 INI 逐个移到 EFMI 的 `EndfieldJiggleBackups/layout-*`。
备份含原始字节、文件时间和 `layout-transaction.json` 清单；旧副本的模型、
贴图、EXE、着色器和其他文件保持原位。没有移除入口的非触摸 Mod 不受影响。
未知 INI、修改过的自有资源和目录链接会阻止自动修复并显示具体路径。
修复失败会回滚本次安装和已移动入口。

所选目标必须仍有可读取的 `EndfieldJiggle.ini` 和 `Passes.ini`。
若这两个文件也已损坏或删除，先在 `Mods` 外完整解压本版拖放包，然后将
旧触摸目录完整移到 `Mods` 外备份，再按正常方式安装。

运行文件的安装前备份另外保存在修复结果显示的目录，可通过“恢复安装前版本”
恢复。此操作不重新启用已隔离的冲突入口；旧入口仍保存在目录修复备份中。

## 纯 Mod 与独立版

纯 Mod 的十五个触摸运行文件与其他两种包相同。手动安装时，先将旧触摸目录
整体备份到 `Mods` 外，再完整解压新包；只改名子目录不能停用根目录 INI。
需要自动修复已有分类布局时，使用本次修订拖放包的配置器。
独立版内的配置器也提供相同修复入口，保留原有独立包结构。

## 验证边界

隔离的官方 EFMI 加载器已复现旧入口冲突，并检查修复前后的加载结果。
自动回归覆盖完整性、残留入口、设置保留、资源补齐和失败回滚。
目录与加载验证不能代替游戏内真实拾取和拖动验收；此修订未启动或注入本机游戏。
