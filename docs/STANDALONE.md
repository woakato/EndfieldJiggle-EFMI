# 独立便携版

2026-10-15 启动流程修订：本包不再直接运行 `Endfield.exe`，改为等待用户从官方游戏
启动器启动。仍使用原有上游 DLL 加载接口，不修改安全策略，也不保证游戏更新后可用。

已有 XXMI / EFMI 的用户继续使用 `drop-in-win64.zip`，解压到现有 EFMI 的 `Mods`
下一个目录，让 `shaders` 与 INI 直接位于其中。只需默认参数的用户可选纯 Mod 包。

没有 XXMI Launcher 的用户使用 `EndfieldJiggleEFMI-v0.2.3-standalone-win64.zip`。
它包含官方 EFMI 1.4.8、官方 XXMI 渲染库 1.2.2、修复原皮黑面的 v0.2.3 触摸 Mod、
现有配置器和本项目的便携启动器，无需另行安装 XXMI Launcher 或 .NET。
“独立”指不依赖 XXMI Launcher 安装，渲染仍使用 EFMI / XXMI 的官方库。

## 首次使用

1. 先通过官方游戏启动器安装、更新游戏，并确认可以正常启动；退出游戏与 XXMI。
   官方游戏启动器可以保持打开。
2. 将整个独立包解压到可写目录，例如 `D:\Mods\EndfieldJiggle`。
   不要放进游戏目录或已有 EFMI 目录，不要只提取一个 EXE。
   优先使用 `D:\EJ` 这类短目录，不要放在多层压缩包目录或项目的 `reports` 深处。
   当前上游库仍用固定长度缓冲区生成着色器缓存名；即使 HLSL 路径不到 260 字符，
   加上缓存后缀仍可能超长并导致游戏退出。启动器会在加载 DLL 前阻止此类路径。
3. 打开 `EndfieldJiggleLauncher.exe`，在“游戏路径（Endfield.exe）”中确认自动找到的路径，
   或点击“选择游戏”选取游戏安装目录里的 `Endfield.exe`，然后点击“等待官方启动”。
   路径用于核对目标，不会直接执行。路径保存在本包的 `launch-settings.json`。
4. 在官方游戏启动器选择 **DirectX 11**，再点击官方的开始游戏。不要在本包开始等待之前启动游戏。
5. 本包检测到所选游戏后尝试加载 EFMI。等待状态显示 EFMI 已加载，之后可关闭本包窗口。
   进入干员总览后使用触摸快捷键；“已加载”不代表触摸已经通过验证。
6. 后续双击 `Start.cmd` 即按保存路径开始等待，仍需通过官方启动器开始游戏；
   未保存路径时显示选择界面。

默认触摸关闭：`Ctrl+Shift+F8` 开关，`Shift+鼠标左键` 拖动，
`Ctrl+Shift+F7` 强制关闭，`Ctrl+Shift+F9` 诊断。
手动启动不能自动附加旧版的 `-force-d3d11` 参数，需要在官方启动器确认 DirectX 11。
只打开官方游戏启动器、不先在本包开启等待，不会自动加载本包。
等待游戏最多 5 分钟，可取消后重新等待。取消不会关闭游戏，也不会卸载已经开始加载的 EFMI。

本包不再为直接启动游戏自动请求管理员权限。若出现拒绝访问，请确认本包程序与官方
启动器的运行权限一致；不要关闭安全软件或反作弊。安全策略拒绝加载时保留日志并停止测试，
不要尝试绕过校验。由官方启动器负责游戏更新、登录与启动。

## 配置和换装

点击“打开配置器”使用原有的键位、参数、Mod 库和换装适配功能。
启动窗口随之关闭，配置器会自动识别本包的 EFMI。关闭程序后，已保存的触摸设置仍然保留；
保存参数或支持的换装 INI 后可回到游戏松开修饰键并按 `F10`。
首次安装或更新运行时需要退出并重新启动游戏。

点击“Mods 文件夹”，将其他换装 Mod 放进本包的 `EFMI/Mods`。
如需触摸适配，从配置器的 Mod 库选择换装并按
`OUTFIT-COMPATIBILITY.md` 操作。第三方 Mod 的额外依赖仍需自行安装。
本包不包含换装模型、纹理或 QAQM；它们不会从你的其他 EFMI 安装自动复制过来。

同一次游戏会话选择一套 EFMI。独立包与原有 XXMI 的 Mod 和参数分别存放，
不要同时从两边启动、不要混用渲染 DLL。

## 目录和恢复

```text
EndfieldJiggle/
  EndfieldJiggleLauncher.exe
  Start.cmd
  standalone-manifest.json
  Licenses/
  EFMI/
    3dmloader.dll
    d3d11.dll
    d3dcompiler_47.dll
    d3dx.ini
    Core/
    Mods/
      EndfieldJiggleEFMI/
        Configurator/EndfieldJiggleConfigurator.exe
```

启动器只在本包保存路径和日志，不安装文件到游戏目录，不修改游戏资源。
渲染库会写入本包的 EFMI 日志、用户配置和缓存。
移除时退出游戏与程序，备份需要保留的 `Mods` 和设置，再删除整个独立包。
继续用官方游戏启动器启动即可。升级时使用新的完整目录，备份并迁移自有
Mod 和配置，不用旧 `d3dx.ini` 或渲染 DLL 覆盖新包。

## 问题反馈

- 找不到游戏：选择包含 `Endfield.exe`、`Endfield_Data`、
  `GameAssembly.dll` 的游戏目录。
- DLL 缺失或校验失败：完整重新解压发布包，保留原文件名和相对路径。
- 5 分钟内没有检测到游戏：确认先点击了“等待官方启动”，再从官方启动器开始游戏。
- 游戏路径不一致：官方启动器可能指向另一份游戏。退出游戏，重新选择实际运行的 `Endfield.exe`。
- Windows 错误码 `740` / `5`：检查本包程序与官方启动器的权限是否一致，不自动提权重试。
- 显示 EFMI 已加载后闪退，崩溃模块为包内 `d3d11.dll`、异常为 `0xc0000417`：
  本机已发现解压目录过深导致缓存文件名超长。先完整重新解压到 `D:\EJ`；
  这不等于所有同类崩溃都由路径导致。仍失败时导出诊断，不要更换系统 DLL。
- 旧手动启动包出现 `299` / `5`，日志停在 `GetModules` / `GetFirstModule`：
  使用进程查询修正版。旧路径检查错误地枚举了游戏模块，尚未调用 EFMI 加载；
  修正版使用有限权限的进程路径查询，但被拒绝时仍停止，不跳过路径核验。
- 等待 EFMI 超时：退出游戏，确认官方启动器使用 DirectX 11，检查运行权限和日志。
  如果安全策略拒绝加载，不要关闭防护或修改反作弊。
- 游戏运行而触摸无效：确认等待流程显示 EFMI 已加载，且本包触摸 Mod 已开启。
  DLL 加载成功仍不能证明 GPU 拾取或触摸成功。不要同时打开另一套 XXMI。
- 启动失败时查看本包 `Logs/launcher.log`。普通包默认关闭详细日志，
  因此不保证存在 `d3d11_log.txt`。需要排查拖动无效果时使用单独的
  诊断版独立包及其 `Collect-Diagnostics.cmd`，见
  [诊断版说明](DIAGNOSTIC-STANDALONE.md)；不要开启 FrameAnalysis 或 `debug = 1`。
  分享前检查导出的诊断归档。

旧启动流程在 2026-10-12 收到用户确认启动成功的反馈，不能用于证明本次修订。
2026-10-15 的手动官方启动流程尚未在游戏内验证；登录、画面与触摸效果需要用户复验。
