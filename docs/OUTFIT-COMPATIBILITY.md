# v0.2.1 换装兼容修复

## 修复范围

v0.2.0 发布包遗漏了旧安装中的换装桥接。本版恢复：

- `Outfits.ini` 的 Begin/End 绘制回调、绘制范围和 12 个已审核程序映射。
- 两个原生颜色拾取程序的换装显式索引范围，避免使用原模型的调用范围。
- 12 个原生 Pass 对已处理换装的排除，避免重复处理原调用。
- 会话存活与绘制条件一致的鼠标判断，支持配置器修改拖动键。

桥接不设置 `filter_index`，不替代换装作者的顶点程序过滤值。
适用于已有 `EJTouch_...` 包装器，或由完整包程序在原目录生成包装器的换装，
并要求使用受支持的原生顶点程序。
不逐角色登记网格，也不自动支持任意自定义顶点着色器。

## QAQM 与解析警告

2026-10-08 报告中的 `k/1.ini`、`swapkey` 警告来自第三方换装的
QAQM UI 命令。状态文件在外部缓存中存在，但 include 列表未加载换装的宿主；
对应的恢复补丁排除已经加载的 UI 宿主，
从同目录 `.qaqm-persistbak` 重建声明，不改写 UI 和换装绘制。
恢复本版桥接并不等于自动恢复那些状态文件。
本基础包不改写第三方 INI，也不附带换装模型或纹理。

遇到 `Unrecognised entry` 时保留第一条完整错误及最新加载器日志。
只将运行变量设为零不能阻止解析 INI；完整目录以 `DISABLED_` 开头
才符合已报告环境的递归排除规则。是否需要修复第三方 namespace，
必须按具体 INI 与日志确认，不能全局删除 `if` 或 `swapkey`。
旧独立补丁只对应当时那套换装的 Bridge ID，不是通用方案。
完整程序可以检查实际 include 图和递归排除规则，只从当前换装对应的
`.qaqm-persistbak` 恢复缺失声明；无法证实的情况会停止，不猜测默认值。
详见[状态恢复](QAQM-STATE-RECOVERY.md)。

## 原目录适配与热加载

选择当前 EFMI `Mods` 内的换装目录，分析后确认“原目录适配”。
程序包装有明确范围的 `drawindexed` / 单实例 `drawindexedinstanced`；
保留作者原绘制、条件分支、注释和资源，原始 INI 以 `.bak` 保存。
备份目录以 `DISABLED_` 开头，不作为另一份换装加载。
自定义顶点/几何着色阶段、动态范围和未支持命令会列出原因，不强行包装。

默认要求退出游戏。可选择游戏内重载模式：先关触摸，切换到其他角色，
关闭 XXMI，完成适配/恢复后再回游戏按 F10。不要在写入期间重载。
EFMI 官方热加载步骤同样要求目标角色移出画面，见
[Mod Hot Load](https://github.com/SpectrumQT/EFMI-Package#mod-hot-load)。
这是用户确认后写 INI，再由 EFMI 重载，不是常驻监控或自动注入。

## 验证边界

文件桥接检查、EFMI 隔离加载/合成绘制、配置保存/恢复和游戏实机验证
分别记录。本版不将隔离测试等同于实机验收。
首次升级基础运行时请完整重启；报告中的 F10 后模型消失仍需游戏内复测。
