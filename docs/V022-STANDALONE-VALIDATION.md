# v0.2.2 独立包验证范围

独立包复用已发布的 v0.2.2 拖放包，触摸运行时、着色器、缓存和配置器字节保持一致。
新内容是便携启动器，以及固定版本的官方 EFMI / XXMI 渲染库。

## 2026-10-15 官方手动启动修订

不再直接启动游戏 EXE，不自动附加启动参数或自动提权；用户先开启等待，
再在官方游戏启动器选择 DirectX 11 并开始游戏。继续使用同一份官方加载库的现有接口。
隔离测试覆盖目标路径、中文目录、多进程、取消、进程退出、两阶段超时、
加载失败不重试及有序日志。模拟进程不运行游戏，不执行真实注入。

普通独立包与诊断独立包共用此流程。新流程的真实游戏启动、登录、DLL 加载、
触摸效果及游戏更新后的兼容性尚未验证；不以旧流程的用户反馈替代本次验证。
本修订不调整反作弊、安全策略或游戏登录数据。
实机日志进一步定位到旧路径核验的 `Process.MainModule` 模块枚举出现 `299` / `5`，
发生在调用 EFMI 加载接口前。进程查询修正版改为有限权限查询路径和退出状态，
增加测试进程实际 Win32 查询与拒绝查询时不加载的检查；不对游戏做自动测试。

## 隔离检查

- 官方 EFMI 1.4.8 和 XXMI-Libs 1.2.2 发布 ZIP 的 SHA-256。
- 三个运行库与包内清单一致，文件缺失或篡改会在启动前报错。
- 游戏路径验证、中文路径、设置保存、无效选择拒绝及有限目录查找。
- 手动启动模式的目标路径核验、官方启动流程提示及 DX11 手动确认提示。
- Windows `740` / `5` 仅提示权限匹配，不自动提权，不启动游戏或结束游戏进程。
- 现有配置器能够自动定位独立包内的触摸 Mod。
- 启动程序的官方库导出解析，以及标准、紧凑尺寸和首次使用空路径界面渲染。
- 新版官方运行库在离线 D3D11 宿主中加载十二个接口着色器，
  外部资源绑定恢复检查通过，加载器没有解析或编译诊断。
- 全部检查只使用 `reports` 内的隔离目录，不启动游戏。

具体结果记录在构建的 `build-report.json`、`smoke-report.json` 和测试报告。
程序界面的“EFMI 已加载”表示加载器报告 DLL 已加载，不表示已经验证角色触摸效果。
离线宿主使用立即加载 INI 的测试配置；生产包沿用 EFMI 的首帧加载配置。
因此离线成功不证明真实游戏启动时机或同进程重载行为已经验证。

## 用户实机测试

2026-10-12，用户反馈修正权限处理后的独立启动器已可正常启动，
此前报告的 Windows `740` 启动错误已解决。这是用户实机反馈，
不是自动化游戏测试，也不代表已确认所有用户环境。

本次反馈未单独确认游戏登录、模型显示、拖动和回弹，以及同进程 `F10` 重载。
本次未替换本机原有 EFMI 或游戏目录，也未自动登录或操作游戏。
已有 XXMI 用户可以继续下载拖放包；独立包无需安装 XXMI Launcher，
但仍使用官方 EFMI / XXMI 渲染库，不是重新实现的游戏渲染引擎。
